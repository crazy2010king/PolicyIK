### 2.4 末端跟踪误差（L8）与**加速度上限**的标定

| 加速度上限（rad/s²） | 轨迹 | 关节误差 max | **末端误差 max** | 判定（≤ 3 mm） |

| **1.0 / 1.2** | 131 点 / 0.65 s | **0.472°** | **2.56 mm**（p95 2.29 / p50 1.23） | ✅ |

### 2.9 急停态（L11 的一部分）：**这台控制器不支持软件急停**

`scripts/estop_fault_test.py` 在真机上尝试用厂商接口注入急停：

| 调用 | 返回 | 含义 |
|---|---|---|
| `rm_set_arm_emergency_stop(True)` | **-4**（0.00 s 返回） | 控制器**超时拒绝** ⇒ 软件急停**不生效** |
| 急停后 `rm_set_realtime_push(enable=False)` | **阻塞 > 8 s** | 一次被拒的调用让同连接的**配置通道**不再返回 |
| 急停后 `rm_get_current_arm_state` | 0（0.01 s） | 指令/状态通道仍正常 |

⇒ 两个结论：
1. **急停必须用物理急停**（《设计文档》§五.2 第 7 闸）；
   `estop_status` 故障链在真机上**无法用软件注入**，
   只能用物理急停 + 人手确认（脚本已就绪：`scripts/estop_fault_test.py`）。
2. **厂商 ctypes 调用没有内置超时** ⇒ 我方新增 `ArmBinding.call(timeout_s=...)`
   与 `SdkCallTimeout`（守护线程 + 超时），并给**所有非实时路径**的 SDK 调用
   加了 2 s 超时（否则一次被拒调用就能挂死收尾流程 / 5 ms 执行环）。

## 四之二、探测副作用与恢复（操作纪律）

第三轮做「控制器限位」探测时，我方脚本按 **0-based** 写限位，
**改动了控制器上 J1 / J2 / J7 的最小限位**（J1 的下限一度被钉在当前位形
14.327° ⇒ 该轴只能单向运动）。

处置：
1. 读回现状（`rm_get_joint_min_pos` / `rm_get_joint_max_pos`）⇒ 确认被改的 3 个轴；
2. 按**未被改动的各轴 + 对称性**推断出厂值
   （J1 ∓125.998°、J2 ∓130.0°、J7 ∓360.0°）写回；
3. **读回校验**：全部 7 轴恢复为出厂值 ✅（见 §2.8 表）。

⇒ **操作纪律（新增）**：写控制器限位前**必须先读**、写完**必须读回校验**，
且 `joint_num` 是 **1-based**；任何写限位的脚本都应遵守「读-改-写-校验」四步。

## 六、现场事件记录：开发机到机械臂的**网卡掉线**（2026-11-20 10:55 起）

在跑完 L12 长稳、做完急停接口探测之后，远端工作站到机械臂网段的链路**掉了**：

```
$ ip -br link | grep enx
enx98fc84e3177a  DOWN  98:fc:84:e3:17:7a  <NO-CARRIER,...>   # USB 网卡，无载波
$ ping -c 3 192.168.1.18      → 100% 丢包
$ nc -vz 192.168.1.18 8080    → TCP_FAIL
$ curl http://192.168.1.18/   → 超时（网页也不可达）
```

* 该网卡原本承载 **192.168.1.198/24**（机械臂网段的**唯一**通路）；
* 掉线后连**网页**也不可达 ⇒ 不是「控制器忙」，而是**链路层就没了**；
* 容器 `ros_dev` 用的�� **host 网络命名空间**（`docker inspect` 里没有自己的 IP），
  所以它也随之无法访问机械臂；
* 我方的软件只对机械臂发 TCP/UDP 命令，**不触碰宿主机的网卡**；
  ⇒ 判定为**现场物理事件**（USB 网卡/网线松动或被拔）。

**恢复步骤（需人在工作站前操作）**

```bash
# ① 重新插拔 USB 网卡 / 网线（或换网口），确认：
ip link show enx98fc84e3177a | grep -o 'LOWER_UP'   # 出现 LOWER_UP 才算链路回来
# ② 恢复地址（若不是 NetworkManager 自动恢复）：
sudo ip addr add 192.168.1.198/24 dev enx98fc84e3177a
sudo ip link set enx98fc84e3177a up
# ③ 验证：
ping -c 3 192.168.1.18 && nc -vz 192.168.1.18 8080 && curl -sI http://192.168.1.18/ | head -1
```

**这条事件恰好证明了阶梯 L0 的价值**：任何一次真机操作前，
先跑 L0（TCP + 网页）就能在 1 秒内判定「链路还在不在」，
而不是在后续步骤里莫名其妙地超时。

> 同时暴露一个**运维缺口**：机械臂侧的心跳/断线告警目前只能在**应用层**
> （状态 age）看到；开发机侧网卡的物理掉线没有任何告警。
> 建议后续在工作站上加一条网卡 carrier 监控（`/sys/class/net/*/carrier`）。
