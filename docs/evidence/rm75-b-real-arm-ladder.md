# 真机证据：RM75-B（192.168.1.18）验证阶梯首轮实测

> **日期**：2026-11-19
> **对象**：睿尔曼 RM75-B（7-DoF），现场 IP `192.168.1.18`，厂商示教器网页 `http://192.168.1.18/`
> **执行环境**：远端工作站 `172.16.119.199`（宿主机，网卡 `192.168.1.198/24`），
> Python 3.12 + `robotic-arm==1.1.7`（导入名 `Robotic_Arm`）+ numpy + PyYAML，
> **零 Drake 依赖**（设备层不需要 Drake）。
> **工具**：`scripts/real_machine_ladder.py`（见 `docs/validation/RM75-B_真机验证阶梯.md`）
> **原始报告**：`docs/evidence/rm75-b-ladder-2026-11-19.json`（本文件的数据源）
>
> ⚠️ **诚实边界**：本轮只跑了**只读级别**（L0–L5、L10）与**离线级别**。
> 运动级别（L6–L9、L12–L13）需要操作者**手持物理急停**在场，
> 本轮**未自动执行** ⇒ 相应指标仍属「未验证」，见 §五。

## 一、结论速览

| 级别 | 状态 | 一句话结论 |
|---|---|---|
| L0 链路与网关 | ✅ PASS | TCP 8080 可连接（0.55 ms）；示教器网页 HTTP 200 |
| L1 SDK 与控制器能力 | ✅ PASS | SDK 1.1.7 可导入；`arm_dof=7`；**控制器代次 = 3** |
| L2 连接与只读状态 | ✅ PASS | 句柄 `id=1`；关节角/位姿/电流/错误码全部读回；**零错误码** |
| L3 UDP 主动上报 | ✅ PASS | 3 s 收 **600 帧**；实测周期 **P50 = 4.998 ms**；**0 帧不完整** |
| L4 使能与就绪 | ❌ FAIL | 7 轴**全部使能**、无错误码，但**机械臂状态 = 9（急停）** |
| L5 运动前静态自检 | ✅ PASS | 关节全在软限位内；围栏零违规；**但高度余量仅 ~1 mm** |
| L6–L9、L12–L13 | ⛔ blocked | 依赖的 L4 未通过 ⇒ 运动级一律被门禁拦住（**符合预期**） |
| L10 安全七闸逐闸 | ✅ PASS | 7/7 闸全部拦下；真机越界目标被安全层拒绝 |

**一句话**：链路、SDK、连接、状态回读、周期标定、静态安全自检、安全七闸
**全部在真机上通过**；唯一的阻塞点是**机械臂当前处于急停状态**——
这正是阶梯要在动真机之前抓出来的东西。

### 2.4 UDP 主动上报周期（L3）

| 指标 | 实测值 | 说明 |
|---|---|---|
| 帧数（3 s） | **600** | 期望 3 s / 5 ms = 600 ⇒ **一帧不丢** |
| 上报周期 P50 | **4.998 ms** | 与期望 5 ms 偏差 **0.03%** |
| P99 / P99.9 / max | 5.222 / 5.326 / 5.342 ms | 抖动极小 |
| 最小周期 | 4.618 ms | |
| 不完整帧（`errCode = -3`） | **0** | 帧完整性校验全程通过 |
| 上报目标 IP | **192.168.1.198** | 自动探测到的本机地址（**不是**机械臂 IP） |

**周期读法定论**（对照实验，宿主机实测）：

| `cycle` | 实测 P50 | 对应读法 |
|---|---|---|
| 1 | **4.998 ms** | 读法 A（单位 = 5 ms 的倍数）✅ |
| 5 | **24.954 ms** | 读法 A（1 × 5 = 5 ms，5 × 5 = 25 ms）✅ |

⇒ 《设计文档》§二.2 写的「`rm_set_realtime_push(cycle=5)` 表示 5 ms」

### 2.5 使能与机械臂状态（L4）

| 指标 | 实测值 |
|---|---|
| 逐轴使能标志 | **7/7 全部 true** |
| 逐轴错误码 | 全 0 |
| `arm_current_status` | **9 = `RM_STOP_E`（急停状态）** |

⇒ **「全部使能」不等于「可以动」**：现场这台臂处于急停态，
必须先在示教器/网页释放急停，运动级才能解锁。阶梯据此把 L4 判为 FAIL，
L6/L7/L8/L9/L12/L13 全部 `blocked`——**这正是门禁该干的事**。

### 2.6 运动前静态安全自检（L5）

| 指标 | 实测值 | 判读 |
|---|---|---|
| 关节在软件软限位内 | ✅ 全部在范围内 | |
| 围栏违规数 | **0** | |
| link7 位置（MDH 正运动学） | `[0.30776, -0.03699, 0.75442] m` | 与控制器自报位姿一致（差 ~1 mm） |
| TCP 高度 | 0.75442 m | 桌面阈值 0.75 m ⇒ **余量仅 ~4 mm** |
| TCP 到基座轴线水平距离 | 0.30997 m | 奇异圆柱 0.15 m ⇒ 余量 0.16 m ✅ |

⚠️ **围栏参数是占位值**：`table_height_m = 0.75` 与现场实际桌面高度几乎重合，
任何向下的小动作都会撞上 G6。**动真机前必须按现场工位标定桌面高度与基座位置**。

### 2.7 安全七闸逐闸注入（L10，离线注入 + 真机围栏拒绝）

| 闸 | 注入方式 | 命中的 reason | 安全态动作 |
|---|---|---|---|
| G1 软限位 | 指令超软限位 | `soft_limit` | clamp |
| G2 单步增量 | 一步跳 1 rad | `delta_clamp` | clamp |
| G3 加速度 | 上一拍速度 2 rad/s | `accel_clamp` | clamp |
| G4 看门狗 | age > 告警周期 | `watchdog` | clamp |
| G5 电流 | 电流 = 阈值 × 2 | `current` | **stop** |
| G6 围栏 | TCP 高度 0.4943 m < 0.75 m | `fence` | **stop** |
| G7 状态 age | age > 4 × 超时阈值 | `state_age` | **stop** |

真机部分：构造一个低于桌面的姿态 → 安全层返回 `fence` 且动作 = `stop` ⇒
**越界目标在真机参数下被正确拒绝**（且**没有下发任何指令**）。

## 三、本轮**修掉的真机缺陷**（都是阶梯跑出来的）

| # | 缺陷 | 症状 | 修复 |
|---|---|---|---|
| 1 | 线程模式常量错误 | `transport.py` 里 `RM_TRIPLE_MODE_E = 3` ⇒ SDK 打印 `Invalid thread mode`，连接拿不到句柄 | 改为 **2**（`device/binding.py` 是唯一真相源） |
| 2 | **从不建立连接** | `SdkTransport` 只 `RoboticArm(...)`，**没调** `rm_create_robot_arm` ⇒ 真机上根本没有链路 | 新增 `device/binding.py::ArmBinding`：建实例 → **建连接** → 校验句柄 → 失败显式报错 |
| 3 | 调用形态错误 | 按「模块级函数」调用（`rm_movej_canfd(joint, follow=...)`），而 SDK 的模块级符号是 ctypes 原函数（签名不同） | 调用路由改为**实例方法优先**（`ArmBinding.call`），模块级仅作兜底 |
| 4 | 逐关节接口按整臂调用 | `rm_set_joint_en_state(bool)` / `rm_set_joint_clear_err()` / `rm_set_joint_min_pos(list)` 与真 SDK 签名不符 | 改为**逐轴**调用（`joint_num` + 值） |
| 5 | 夹爪接口签名不符 | `rm_set_gripper_position(pos)` 缺 `block` / `timeout` | 补齐 `(position, block, timeout)` |
| 6 | 状态回读永远是 `None` | `SdkTransport.read_state()` 依赖一个从未被设置的 `_latest_frame` ⇒ 安全闸/状态机拿不到任何真机状态 | 新增 `device/realtime.py`：配置主动上报 + 注册回调 + 解码进 `StateSource`；`SdkTransport.attach_state_source()` |
| 7 | 顶包子模块缺失 | `Robotic_Arm.__init__.py` 是空的 ⇒ `Robotic_Arm.rm_robot_interface` 属性不存在 | 显式 `importlib.import_module("Robotic_Arm.rm_robot_interface")` |
| 8 | 退出期随机段错误 | 删句柄 / 回调对象被 GC 后，SDK 的 UDP 线程回调野指针 ⇒ `Segmentation fault`（连报告都写不出来） | 回调对象**进程级保活**；不删句柄；报告写完后用 `os._exit` 退出 |

## 四、**仍未验证**的指标（不得当作通过）

| 指标 | 目标 | 需要哪一级 | 为什么本轮没做 |
|---|---|---|---|
| 5 ms 透传周期抖动 | P99.9 < 0.5 ms | L7 | 运动级，需手持物理急停的操作者在场 |
| 末端跟踪误差 | < 3 mm | L8 + 外部测量 | 需运动 + 标定板/相机 |
| 急停响应时间 | < 100 ms | 人工计时 | 需物理急停 + 录像 |
| 100 Hz × 30 min / 8 h 长稳 | 无异常停机 | L12 | 运动级 |
| 五类故障注入的物理验证 | 全部进入安全态并恢复 | L11 | 需人为拔网线 / 断电 |
| 双臂共同点偏差 / 相对位姿搬运成功率 | < 0.5 mm / ≥ 95% | L13 | 第二台臂（`.19`）尚未接入 |

> 工具在这些情况下会输出 `SKIP` 或 `manual` / `blocked`，
> 并**逐条列出未验证指标**（沿用 `device/hardware_gate.py` 的诚实纪律）。

## 六、**必须先做**的三件事（动真机之前）

1. **释放急停**：现场机械臂 `arm_current_status = 9`（急停），先在示教器/网页释放，
   否则 L4 永远不过，运动级永远被门禁拦住；
2. **标定电流阈值**：静态保持时 J2 已达 **-1824 mA**，而兜底阈值只有 1500 mA
   ⇒ G5 会误触发。把 `devices/rm75_b_192_168_1_18.yaml` 的
   `current_thresholds.calibrated` 与逐轴值按实测回写；
3. **标定围栏参数**：`table_height_m` 目前是占位值，实测 TCP 高度余量只有 ~4 mm。
   按现场桌面高度与基座位置回写 `fence` 段，再复跑 L5。
