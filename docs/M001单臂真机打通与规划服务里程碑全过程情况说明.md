### S07 自研规划服务 `rm_planner`（risk: medium）

- **落点（D027）**：`rmctl/planner_service/`（进程角色名 `rm_planner`，独立可杀可重启），不新建第五个包、不改契约层表；复用 `rmctl.planner/verify/retime/model/paths` 作为唯一真值。
- **关键偏差（D028，amends D003）**：原设想"自研 Task 节点插入官方 YAML 管线"**不可行**——实测 tesseract-robotics-nanobind 0.35.0.8 的 Python 绑定**没有任何注册自定义 TaskComposer 节点的 API**，管线内自研必须写 C++ 工厂库，违反零编译主线。改为"服务层 Python 后置校验"：规划成功后依次跑 `rmctl.verify` 四道校验，SUCCESS 语义仍是"四道全过"。
- **超时/可中断机制（D029）**：每请求独占 worker 子进程（`python3 -m rmctl.planner_service.worker`），worker 启动即 `RNG_setSeed(seed)`；父进程持 deadline，到点 **SIGKILL** + waitpid 回收 → `status=TIMEOUT`（带被中断阶段）；cancel 走同一路径 → `CANCELLED`；worker 异常退出 → `FAILED` 且服务进程存活。理由：实测 `TaskComposerFuture` 只有 `ready/valid/wait/waitFor/context`，**无 cancel**，`waitFor(float)` 绑定自身抛 TypeError，进程内 taskflow 是原生代码无法从 Python 打断。
- **验证**：`build/reports/s07_planner_acceptance.json` 三条验收全过——① 规划超时被服务端强制中断；② 服务崩溃不影响运动执行；③ 同请求同种子 `trajectory_digest` 逐点一致（跨进程 3/3 一致）。
- **未实证**：真机版崩溃隔离（"rm_runtime 执行中 `kill -9 rm_planner` 后真机运动是否继续"）——S12 已把它显式登记进未闭合清单，R008 保持 active。

**踩坑清单（复盘价值最高）**

1. `rmctl/hwcollect.py` 的 FK 采样循环 `goal = 当前关节角` → N 组样本其实是同一位形重复，交叉校验形同虚设。
2. numpy `einsum("ijk,ijk->ij", Rf, Rf)` 求的是行内积而非 Frobenius 内积；求 `tr(R_i^T R_j)` 必须写 `einsum("ijk,ljk->il", Rf, Rf)`。
3. 反向依赖断言必须用**子进程隔离**（只把被测包根放进 PYTHONPATH），不能断言当前 pytest 会话的 `sys.modules`。

6. 解析带转义竖线的 Markdown 表格必须用 `re.split(r"(?<!\\)\|", ...)`。
7. `docs/code_doc` 是指向仓库外部的符号链接，仓库内正本必须在 `docs/` 目录（如 `docs/rm_hw_bridge硬件适配层说明.md`），再镜像一份到符号链接指向的文档集。
8. 仓库 `.gitignore` 有全局 `vendor/` 规则，必须为 `dualarm_ws/src/rm_hw_bridge/vendor/` 加反向 `!` 规则，否则头文件与 PROVENANCE 不会被跟踪。
