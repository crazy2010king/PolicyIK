## 1. 字段含义与单位约定

### 1.1 单位总表（**唯一口径**，脚本与文档必须一致）

| 量 | 单位 | 说明 |
|---|---|---|
| 关节读数（SDK `rm_get_joint_degree`、零位 `zero_deg`） | **度 (deg)** | 真机 API 一律用度；进入内部计算前必须转弧度 |
| 内部关节角 / 位置 / 速度 | **rad / rad/s** | 规划、FK、限值校验全部用 SI 弧度制 |
| 加速度上限 `acceleration` | **rad/s^2** | 基线与 `joint_limits.yaml` 的口径 |
| 加加速度上限 `jerk` | **rad/s^3** | 同上 |
| TCP 位置重复性 | **mm** | 只表示"多次到同一点的散布"，**不等于绝对精度** |
| FK 交叉校验位置偏差 | **mm** | 判定阈值 1 mm |
| FK 交叉校验姿态偏差 | **deg** | 判定阈值 0.05° |
| 实时上报周期 | **ms** | 必须是 5 ms 的整数倍 |

> 度→弧度的换算点必须收敛到**一处**（`rmctl/fk_cross.py` 的 `_to_rad()`、
> `rmctl/hwcollect.py` 的 `DEG2RAD`），否则口径会漂。

### 1.2 `zero_baseline.yaml`

| 字段 | 含义 |
|---|---|
| `arm` | `left` / `right` |
| `firmware` / `teachpendant_version` | 控制器固件版本、示教器版本 |
| `joints[].zero_deg` | 每关节零位读数（**度**）；未实测写 `null` |
| `joints[].groove_photo` | 该关节机械凹槽对齐照片的引用 |
| `groove_photos[]` | 凹槽对齐照片证据列表（`status=measured` 时至少一条） |
| `fk_recheck.max_pos_dev_mm` / `max_ori_dev_deg` | FK 交叉校验实测偏差 |
| `fk_recheck.method` | 复测方法（如"20 组随机位形，控制器位姿 vs 自研 FK"） |
| `fk_recheck.conclusion` | 结论文字 |
| `fk_recheck.controller_pose_usage` | 固定写「仅用于 FK 交叉校验，不得作为规划真值」（R003） |
| `recalibration_triggers[]` | 重标触发条件：换电池 / 拆装 / 机械冲击 / 固件升级 |
| `status` | `pending`（未实测）/ `measured`（已实测带证据）/ `blocked`（被阻塞，附原因） |

### 1.3 `measured_limits.yaml`

| 字段 | 含义 |
|---|---|
| `joints[].acceleration` | `{value, unit, source, method, samples}`：`value`=rad/s^2 |
| `joints[].jerk` | 同上，`value`=rad/s^3 |
| `source` | 数据来源（可追溯到哪次实验/哪个文件），**不得为空** |
| `method` | 采集方法（阶梯速度包络 / rm_movej 固定目标 N 次 …），**不得为空** |
| `samples` | 样本数，**≥ 3**（单次极值不算证据） |
| `tcp_repeatability` | `{value_mm, unit, source, method, samples}`，重复性 ≠ 绝对精度 |
| `udp_period_ms` | 实时上报周期（5 ms 的倍数） |
| `status` | 同上；`status=measured` 时数值不得高于 `joint_limits.yaml` 的已生效限值 |

### 1.4 `version_matrix.yaml`

`controller_firmware` / `teachpendant` / `rm_api2_sdk` / `ros2_rm_robot_tag` /
`tesseract_robotics_nanobind` / `libstdcxx` / `python` / `os` / `container_image`——
逐项填字符串，未知写 `null`（`status=measured` 时必须全部有值）。

### 1.5 `network_plan.yaml`

| 字段 | 含义 |
|---|---|
| `arms.left/right.ip` | 控制器 IP（左 192.168.1.18、右 192.168.1.19） |
| `arms.*.tcp_port` | TCP 控制端口 8080 |
| `arms.*.udp_port` | UDP 上报端口 8091 / 8092（**左右臂不得相同**） |
| `realtime_report.period_ms` | 上报周期（5 ms 的倍数） |
| `realtime_report.cycle_multiple_ms` | 周期倍数基准 |
| `realtime_report.mode` | 必须 `triple_thread`（**不开三线程收不到 UDP 实时上报**） |
| `constraints.single_client_per_endpoint` | 必须 `true`：同一 ip:port 只允许一个客户端 |
| `constraints.triple_thread_mode` | 必须 `true` |
| `constraints.wired_direct` | 有线直连（不走交换机/路由） |

## 2. 每类基线的采集命令与数据来源

所有实验都由 `rmctl.hwcollect` 承担（`python3 -m rmctl.hwcollect <experiment>`），
**窗口内只跑脚本、只落数据**——不交互式调试。

| 实验 | 产出基线字段 | 命令 | 数据来源 |
|---|---|---|---|
| `udp_stability` | `measured_limits.udp_period_ms`、网络规划确认 | `python3 -m rmctl.hwcollect udp_stability --arm left --duration-s 600 --out <dir>` | 真机实时上报流（聚合统计 + 抽样帧） |
| `ladder_acc_jerk` | `measured_limits.joints[].acceleration/jerk` | `python3 -m rmctl.hwcollect ladder_acc_jerk --arm left --trials 3 --out <dir>` | 固定姿态逐关节阶梯速度，**多次采样取包络（保守下界）** |
| `tcp_repeatability` | `measured_limits.tcp_repeatability` | `python3 -m rmctl.hwcollect tcp_repeatability --arm left --repeats 30 --target <7 个关节角(度)> --out <dir>` | 30 次 `rm_movej` 到同一点，统计散布 |
| `fk_cross` | `zero_baseline.fk_recheck` | `python3 -m rmctl.hwcollect fk_cross --arm left --samples 20 --out <dir>` | 20 组随机位形的 (q, 控制器位姿) 样本对 |
| `zero_capture` | `zero_baseline.joints[].zero_deg`、`groove_photos[]` | `python3 -m rmctl.hwcollect zero_capture --arm left --photo <照片引用> --out <dir>` | 示教器受控流程后的读数快照 + 照片 |
| `estop_drill` | （安全演练证据，不进基线数值） | `python3 -m rmctl.hwcollect estop_drill --arm left --out <dir>` | 软停/急停的 SDK 返回码、错误码、状态快照 |
| （环境） | `version_matrix` | 现场填：`python3 -c "import tesseract_robotics as t; print(t.__version__)"` 等 | 控制器/示教器界面 + 本机工具链 |

`fk_cross` 的结果要再过一遍台架：

```bash
# 把 hwcollect 采到的样本对整理成 JSON 数组（joint_deg + controller_pose）
python3 -m rmctl.fk_cross --samples samples.json --out fk_report.json
# 退出码：0 通过 / 3 偏差超限 / 2 输入非法
```

报告里的 `position.max`（mm）、`orientation.max`（deg）、`violations`（越界样本索引）、
`attribution`（系统性偏移还是单关节误差）就是要回填进 `fk_recheck` 的内容。

## 3. 真机窗口执行手册

### 3.1 前置门禁（窗口开始前逐项确认并留证）

| # | 检查 | 命令 / 方法 | 通过标准 |
|---|---|---|---|
| 1 | RM-API2 1.1.7 到位 | `ls .deps/rm_api2/libapi_c.so` 或 `echo $RM_API2_LIB` | 文件存在（入库与否另行决策） |
| 2 | 白名单符号齐全 | `nm -D .deps/rm_api2/libapi_c.so \| grep rm_` | 白名单符号全部导出 |
| 3 | 网络连通 | `ping 192.168.1.18`、TCP 8080 | 通 |
| 4 | UDP 端口未被占用 | `ss -lun \| grep 8091` | 无占用（**同一 ip:port 单客户端**，上一个进程没退干净会静默失败） |
| 5 | 环境可导入 | `source scripts/rmenv.sh && python3 -c "import rmctl.hwcollect"` | 无异常 |

任何一项不通过 → **不要在真机窗口里现场调代码**，改为把相关基线条目置
`status=blocked` 并写明阻塞原因与已尝试的动作。

### 3.2 窗口内执行顺序（建议）

```bash
source scripts/rmenv.sh
OUT=<本次窗口的输出目录>          # 不要写进 workcell/baselines（那是基线，不是原始数据）

# 0) 离线预演，确认脚本本身能走通落盘路径（不碰真机）
for e in udp_stability ladder_acc_jerk tcp_repeatability fk_cross estop_drill zero_capture; do
  python3 -m rmctl.hwcollect "$e" --dry-run --out "$OUT/dryrun"
done

# 1) 实时上报稳定性（10 分钟）
python3 -m rmctl.hwcollect udp_stability --arm left --duration-s 600 --out "$OUT"

# 2) TCP 重复性（≥30 次到固定目标）
python3 -m rmctl.hwcollect tcp_repeatability --arm left --repeats 30 \
        --target <7 个关节角(度)> --out "$OUT"

# 3) FK 交叉校验（20 组随机位形）
python3 -m rmctl.hwcollect fk_cross --arm left --samples 20 --out "$OUT"

# 4) 阶梯 acc/jerk（固定姿态逐关节阶梯速度，取包络）
python3 -m rmctl.hwcollect ladder_acc_jerk --arm left --trials 3 --out "$OUT"

# 5) 零位读数（示教器流程完成后）
python3 -m rmctl.hwcollect zero_capture --arm left --photo <照片引用> --out "$OUT"

# 6) 急停演练（软停 + 急停各一次；先做安全检查）
python3 -m rmctl.hwcollect estop_drill --arm left --out "$OUT"
```

急停演练的安全前提（**人不在工作半径内、无设备、示教器在手边**）：
急停后需在示教器上清错并重新使能，**本项目不自动清错、不自动续跑**。

### 3.3 回填入库

1. 把真实读数写进 `workcell/baselines/{zero_baseline,measured_limits,version_matrix}.yaml`，
   `status` 改 `measured`，每条数值补齐 `source` / `method` / `samples`，
   `captured_at` 填采集时间；`network_plan.yaml` 按实连情况确认端口。
2. `version` 字段**单调递增**（基线修订号，不能倒退）。
3. 用回填工具把 acc/jerk 写进限值文件（见第 4 节）。
4. FK 复测结论写进 `zero_baseline.fk_recheck`。
5. 校验：`python3 -m rmctl baseline check`（退出码 0），
   `python3 -m rmctl doctor` 的 `limits:measured` 从 INFO 变 PASS。

**窗口不可用时**：把相关条目置 `status=blocked` 并写明阻塞原因与已尝试的门禁动作
（例如"RM-API2 未到位，`/opt /usr/local /root /home` 均无 `libapi_c.so`"）。
**绝不允许写入任何编造的数值或"已完成"字样。**

## 4. 实测限值回填（apply_measured_limits.py）

`joint_limits.yaml` 里的 `acceleration=5.2359` / `jerk=30.0` 是**保守占位值**
（文件头明说"实测后更新"）。官方从未给出 RM75 的加速度数值（只有 RM65 的
600°/s² ≈ 10.47 rad/s² 可参考），所以回填必须由真机实测驱动。

### 4.1 用法

```bash
# 干跑：只打印逐关节 diff，不写盘（先看这个）
python3 dualarm_ws/src/rm_description/scripts/apply_measured_limits.py --dry-run

# 保守回填（默认）：新值 = min(实测值, 现值)，只可能更保守
python3 dualarm_ws/src/rm_description/scripts/apply_measured_limits.py

# 显式采用实测值（放宽时会给 WARN，需评审）
python3 dualarm_ws/src/rm_description/scripts/apply_measured_limits.py --mode measured

# 机器化
python3 dualarm_ws/src/rm_description/scripts/apply_measured_limits.py --json
```

退出码：`0` 成功 / `2` 输入非法（文件缺失、YAML 解析失败）/ `3` **拒绝回填**（校验不通过）。

### 4.2 三条红线（任一不满足 → 拒绝回填，绝不写入）

| 红线 | 判定 | 拒绝码 |
|---|---|---|
| 基线未实测 | `status != measured` | `baseline_not_measured` |
| 单次极值污染 | `samples < 3`（或不是整数） | `insufficient_samples` |
| 来源不可追溯 | `source` / `method` 为空 | `missing_source` |
| 数值缺失 | `value` 为 `null` | `missing_measurement` |
| 单位不符 | `unit != rad/s^2`（或 `rad/s^3`） | `unit_mismatch` |
| 非正 / 非有限 | `value <= 0` | `non_positive_value` |
| 超出物理合理性上限 | acc > 100 rad/s² 或 jerk > 1e4 rad/s³ | `implausible_value` |
| 限值文件缺该关节 | `rm75_arm` 里没有该关节 | `joint_limits_missing_joint` |

> 物理合理性上限是"绝对封顶"：RM75 官方没给过加速度数值，把 acceleration 写到
> 100 rad/s²（≈5700°/s²）以上已不可能是本机真实上限；jerk 超过 1e4 rad/s³ 同理。
> 超过上限 → 拒绝回填，而不是把保护阈值写成荒谬值。

### 4.3 写盘约定（可 diff、可评审，D001）

* **只做行内数值替换**：文件原有注释逐字保留（文件头说明、每个关节行尾的
  `±178°, 180°/s` 等）；
* 文件尾追加"实测限值回填记录"注释块：回填日期、基线来源与版本、模式、
  逐关节 `source | method | samples`；
* 原子写盘（先写 `.tmp` 再 `os.replace`），中途失败不会把限值文件写坏；
* 同步刷新 `build/model/joint_limits.yaml`（机器本地的物化副本，gitignore）——
  `rmctl.paths.joint_limits_path()` 优先读这一份，**不刷新就等于没回填**。

## 5. 回填后回归口径

回填改变了 `joint_limits.yaml` 的生效限值，必须验证**规划链路**在新限值下的行为。
两个关键函数：

* `rmctl.verify.check_limits(model, points, times)` —— 四道校验的**限位/时间可实现性**那一道，
  逐关节检查位置、速度、加速度、jerk 是否超限；
* `rmctl.retime.required_scale(model, times, points)` —— 保路径重定时需要的最小时间缩放系数
  `s ≥ 1`（几何路径不变，只走得更慢更平滑）。

### 5.1 判定口径（两种都是**预期行为**，不得靠调阈值掩盖）

| 新限值 | 期望行为 |
|---|---|
| 更严（实测值小于现值） | `check_limits` 报超限 → 由保路径降速（`s > 1`）兜底 → 降速后四道校验通过 |
| 更松（实测值大于现值） | 四道校验直接通过，`required_scale == 1`，不触发降速 |

### 5.2 复现步骤（本次已实跑，结论见下）

```bash
source scripts/rmenv.sh
# 1) 生成一条 demo 轨迹
python3 -m rmctl plan --goal 0.6,0.5,0.4,0.3,0.25,0.2,0.15 --out demo_traj.json
# 2) 用新限值校验这条轨迹
python3 -m rmctl check --traj demo_traj.json
# 3) 看保路径降速系数（rmctl.retime.required_scale）
python3 -c "
import sys; sys.path.insert(0, 'dualarm_ws/src/rmctl')
from rmctl.model import Model; from rmctl.retime import required_scale
import json; d = json.load(open('demo_traj.json'))
m = Model(); print('required_scale =', required_scale(m, d['times'], d['points']))"
```

### 5.3 本次实跑记录（demo 轨迹 102 点 / 5.711 s）

| 限值场景 | `check_limits` 问题数 | `required_scale` | 结论 |
|---|---|---|---|
| 当前限值（acc 5.2359 / jerk 30.0） | 0 | 1.0000 | 四道校验直接通过 |
| 更严（acc 0.5 / jerk 5.0） | 8（如"关节 joint1 加速度超限：0.5555 > 0.5000 rad/s²"、"jerk 超限：24.5569 > 5.0000 rad/s³"） | 3.2401 | 校验拦下 → 降速 ×3.2401 后剩余问题数 0（保路径降速兜底生效） |
| 更松（acc 100 / jerk 1000） | 0 | 1.0000 | 直接通过，不触发降速 |

**已知口径盲区**：`check_limits` 只检查**正向**峰值（`arr.max()`），而
`required_scale` 用 `abs()`——因此**负向**的加速度/jerk 峰值不会被 `check_limits`
报出来，但会被保路径降速覆盖（降速系数按绝对值计算）。这属于"校验比降速宽松"，
在回填更严的限值时不会造成漏拦（降速仍会兜底），但会让"校验通过"的表述偏乐观。
